# Known limitations and verification status (v0.3.0a1 Alpha)

This document identifies risks to be checked before a stable release. It is not a claim that they were reproduced by the package creator in every environment.

- **Dictionary contracts:** parameters represented separately from nested field structures may not be consistently included in structural equality and schema fingerprinting.
- **Incremental cache:** exceptional conditions after cache hits may not always produce clean inspection-error results. Use full audits for high-assurance workflows pending additional validation.
- **Contract type validation:** unsupported Arrow type identifiers may not always be rejected early.
- **Hosted CI:** cross-platform GitHub Actions success is not established by merely including workflow files.
- **Performance:** no independently verified performance advantage is asserted in this public Alpha readme.
- **Package distribution:** the source is provided for evaluation. PyPI availability is not asserted.
- **Temporal unit precision vs. dynamic range:** a finer time unit increases precision but reduces the representable dynamic range of the underlying signed 64-bit integer. For example, `timestamp[ns]` can only represent timestamps between 1677-09-21 and 2262-04-11, and `duration[ns]` is limited to approximately ±292 years. Because `parquet-guard` performs zero-data-scan metadata inspection, it cannot inspect row values. In permissive mode, temporal precision widening is classified as a warning (`TEMPORAL_OVERFLOW_RISK`) to alert users to potential `ArrowInvalid` casting failures in downstream readers. Use strict mode if identical temporal resolution must be enforced.
- **Consumer contract specification vs. observed engine behavior:** Downstream consumer impact analysis evaluates compatibility against fields, nested paths, types, nullability, and policies declared in `ConsumerContract`. Unmentioned columns are permitted unless `allow_extra_fields=False`. While `tests/test_consumer_intelligence.py` verifies alignment against real PyArrow reader/cast execution, engine-specific runtime quirks in external engines (e.g., DuckDB, Polars, Spark, Trino) beyond Arrow type/nullability/dimension semantics depend on accurate contract declarations. Unparseable or unrecognized Arrow type strings are classified as `UNCERTAIN` (fail-closed for critical requirements).
- **Synthetic migration sandbox data & business semantics:** Sandbox verification utilizes deterministic synthetic data generation (`generate_synthetic_parquet_table()`) covering type boundary extremes, nulls, and overflow thresholds, and separates `transformation_succeeded`, `schema_matched`, `value_invariants_passed`, `consumer_compatible`, and `deployment_ready` (`readiness_status`). Operations marked `requires_business_semantics=True` are classified as `UNCERTAIN_SEMANTICS` (`deployment_ready=False`) because domain-specific business rules cannot be proven from synthetic data alone.
- **AI evaluation scope (Offline Mock vs. Live LLM):** Running `parquet-guard eval-ai --provider mock` validates offline harness integrity, prompt-format parsing, citation support verification, counterexample detection, and deterministic fallback invariants across 64 synthetic scenarios. It does not measure live remote LLM reasoning accuracy unless invoked with a live provider (`--provider openai`).
- **MCP server transport & sandboxing:** The Model Context Protocol server operates over standard I/O (stdio), enforces JSON-RPC 2.0 error framing (`-32700`, `-32600`, `-32601`, `-32602`), bounds JSON payload sizes and synthetic `sample_rows`, refuses to overwrite existing HTML reports unless `overwrite=True`, and sandboxes file access strictly within `--allowed-dir`. In multi-tenant environments, ensure the spawning agent process runs with least-privilege filesystem permissions.

See `tests/` and submit reproducible bug reports through GitHub Issues. Before declaring a stable release, fix or explicitly constrain the affected capabilities and run a real platform test matrix.
